# Native OpenCode V2 integration

## Context

The program story of epic `opencode2`: refactor ArggonManager into a maximally
native, maximally efficient OpenCode V2 citizen **without changing what it is**
(git-native tracker, one rules kernel, claim → worktree → PR → review → merge →
done). Contracts:

- Spec: [spec-opencode2-009](../../../../docs/specs/spec-opencode2-009.md)
  (invariants I1–I6, out-of-scope, program acceptance).
- Plan: [plan-opencode2-009](../../../../docs/plans/plan-opencode2-009.md)
  (waves W0–W7, T1–T16, dependencies, rollback).
- Decision: [ADR 0010](../../../../docs/adr/0010-opencode2-native-architecture.md)
  (two layers, one logic path, vendored plugin policy).
- Research: [exploration-opencode-v2-native-009](../../../../docs/explorations/exploration-opencode-v2-native-009.md).

Integration branch: `opencode2` (long-lived); wave items branch from it and
merge back. `main` stays untouched by product decision (2026-09-18) — adopters
who want the native OpenCode V2 surface use `opencode2`; `main` merges flow in
as needed.

## Acceptance

- [ ] W0 — ADR 0010 Proposed, spec + plan merged, tracker restructured under
      epic `opencode2` (task-opencode2-plan, task-opencode-v2-adr).
- [x] W1 — declarative seam generated by `init` (config only when the adopter
      has none, agents, commands, slim AGENTS.md) with provenance, parity and
      JSON tests; `doctor` OpenCode checks; playbook + docs
      (task-opencode-v2-spec, task-opencode-v2-doctor, task-opencode-v2-playbook).
- [ ] W2 — vendored plugin: MCP auto-registration, failure isolation, smoke
      harness with `opencode run` evidence (task-opencode-v2-plugin).
- [x] W3 — session context: item correlation, bounded injection, rename,
      hygiene signal, MCP `_meta.sessionID` attribution
      (task-opencode-v2-plugin, task-opencode-v2-mcp-meta).
- [ ] W4 — orchestration: coordinator/worker/reviewer agents, review + done
      commands, permission probes, scripted end-to-end wave
      (task-opencode2-orchestration).
- [ ] W5 — methodology commands + skill progressive disclosure with parity tests
      (task-opencode2-methodology).
- [ ] W6 — measured context/token optimization with before/after evidence
      (task-opencode2-context).
- [ ] W7 — dogfood + release: this repo self-hosts the surface, upgrade path
      proven, docs current, spec/plan flipped `implemented`, program PR merged
      (task-opencode2-dogfood).
- [ ] Essence guardrails verified end-to-end: CLI/MCP identical with the plugin
      absent; no rule logic outside the kernel; every generated artifact has
      provenance and a parity test (spec I1–I6).

## Notes

  reliance on inert V2 surfaces (`instructions` config array, agent `request`
  overlays, session sharing), plugin worktree strategy in this program.
