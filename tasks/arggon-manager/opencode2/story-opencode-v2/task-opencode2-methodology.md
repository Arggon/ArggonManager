# Methodology commands and skill progressive disclosure

## Context

W5 of [plan-opencode2-009](../../../../docs/plans/plan-opencode2-009.md): the
methodology pipeline (explorations, ADRs, specs, plans, playbooks) becomes
native V2 workflow entry points, and the monolithic `arggon-cli` skill
(313 lines, everything in the body) is refactored for progressive disclosure so
the model loads detail on demand instead of carrying it on every prompt.

## Acceptance

- [ ] Commands generated by `init` (or documented from the seam spec):
      `/arggon-spec`, `/arggon-adr`, `/arggon-explore`, `/arggon-playbook`,
      each a Markdown prompt template that drives the existing CLI scaffolds
      (`spec new`, `stack explore`, `playbook new`) plus `spec validate` /
      `spec analyze` verification; no shell blocks with argument placeholders.
- [ ] Skill refactor: `skills/arggon-cli/SKILL.md` keeps the umbrella (when to
      use, install, work loop) and moves operational detail into
      `references/` files (json contract, methodology, orchestration, pitfalls);
      V2 lists supporting files and the agent reads them on demand.
- [ ] Source/bundle parity: `skill-copy.test.ts` and `skills:sync` stay green;
      reference files are bundled and drift-tested like `SKILL.md`.
- [ ] Evidence: a real session shows the reference being read on demand (not on
      load), and `/arggon-spec` scaffolds + validates a spec on a fixture.
- [ ] Docs travel: `docs/agents.md` §Reference integrations and the playbook
      updated in the same PR.

## Notes

- Depends on task-opencode-v2-spec for the generation contract; the skill split
  itself is independent of the plugin.
- Keep the advertised skill description short and stable — it is what the model
  sees per step.
