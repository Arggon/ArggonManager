# Spec and plan: generated .opencode seam (config, agents, commands)

## Context

Phase 1 of [story-opencode-v2](./story-opencode-v2.md) is the declarative
OpenCode V2 seam generated by `arggon init`, per the research in
[exploration-opencode-v2-native-009](../../../../docs/explorations/exploration-opencode-v2-native-009.md).
Non-trivial feature: per [docs/agents.md](../../../../docs/agents.md) §5 it
needs a spec **before** implementation and a plan breaking it into ordered
tasks. Blocked by task-opencode-v2-adr for the architecture decision.

Key inputs from the research: V2 config precedence (`.opencode` overrides direct
config), MCP registration under `mcp.servers`, agent frontmatter
(`mode`/`permissions`/`steps`), commands as Markdown prompt templates, and the
existing never-overwrite + `x-generated` provenance machinery
(`cli/src/docs.ts`, `cli/src/init-docs.test.ts`).

## Acceptance

- [ ] Spec in `docs/specs/spec-<slug>-NNN.md` with purpose, synopsis,
      invariants, JSON/payload notes, and acceptance criteria.
- [ ] Invariants explicit: generate the OpenCode config only when the adopter
      has no `opencode.json(c)` nor `.opencode/opencode.json(c)`; never
      overwrite adopter files; generated JSON stays valid JSON; re-runs follow
      the untouched/modified/backup semantics of `init`; `.mcp.json` for other
      clients is preserved.
- [ ] Agent design mapped to the repo's own orchestration: coordinator
      (primary), worker (subagent, one item per worktree), reviewer (subagent,
      edit-deny permission set per the review bar in engineering.md).
- [ ] Command design: `/arggon-next`, `/arggon-claim`, `/arggon-done`,
      `/arggon-handoff` as prompt templates that call the MCP tools; **no
      shell blocks with argument placeholders** (documented as executing
      outside tool permissions).
- [ ] Plan in `docs/plans/plan-<slug>-NNN.md` with ordered tasks and verifiable
      criteria: config generation, agent templates, command templates,
      provenance/checksum integration, tests mirroring `init-docs.test.ts`
      (created/skipped/modified/backup), smoke proof on a fixture.
- [ ] Spec and plan statuses flipped to `implemented` in the landing PR.

## Notes

- The dependency on the ADR is about package/distribution shape, not about
  whether the seam is needed — the research already recommends it.
- Keep generated artifacts small: a config stanza, three agent files, four
  commands. No `.opencode/plugins/` here (that is task-opencode-v2-plugin).
