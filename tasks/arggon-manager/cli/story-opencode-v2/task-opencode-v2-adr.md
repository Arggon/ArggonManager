# ADR 0010: OpenCode V2 integration architecture

## Context

The research spike
([exploration-opencode-v2-native-009](../../../../docs/explorations/exploration-opencode-v2-native-009.md))
recommends a staged integration: a declarative `.opencode/` seam generated by
`arggon init` (Phase 1), an optional behavioral OpenCode V2 plugin (Phase 2),
and TUI/SDK embedding deferred (Phase 3). Cross-cutting decisions are still
open and must be recorded before implementation: how the plugin is distributed
(published package vs vendored template copied by init), how V2 API churn is
absorbed (version pinning, feature detection, revisit trigger), and what the
integration must never do (fork the rules, make the core CLI depend on
OpenCode).

Per [docs/engineering.md](../../../../docs/engineering.md), a decision that
introduces a new top-level package or a cross-cutting architecture requires an
ADR. 0010 is the next free number (`0009` is item priority and ranking).

## Acceptance

- [ ] `docs/adr/0010-<slug>.md` written with the documented minimum structure
      (Context, Decision, Consequences, Alternatives considered); status
      `Proposed` in the PR, `Accepted` on merge.
- [ ] Research section links
      [exploration-opencode-v2-native-009](../../../../docs/explorations/exploration-opencode-v2-native-009.md).
- [ ] Decides, with rationale: the Phase 1 generated file set (config, agents,
      commands) and its never-overwrite contract; plugin distribution
      (published package vs vendored template); version pinning + feature
      detection + revisit trigger; the explicit optionality of the plugin.
- [ ] Alternatives documented at minimum: A (status quo), C-only (plugin without
      declarative seam), D (SDK embedding inside the CLI).
- [ ] Non-goals stated: rules stay in `cli/src/rules.ts`; no OpenCode dependency
      in the core CLI/MCP; no reliance on inert V2 surfaces.
- [ ] Conventions/doc updates travel with the ADR (engineering.md ADR list if it
      enumerates decisions).
