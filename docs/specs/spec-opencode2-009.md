# Spec: OpenCode2 complete refactor (opencode2-009)

## Purpose

OpenCode V2 is the primary runtime where ArggonManager's humans and agents work.
This spec is the **program contract** for refactoring ArggonManager into a
maximally native, maximally efficient V2 citizen **without changing what
ArggonManager is**: a git-native tracker plus a rules kernel plus a working
method.

The program exists because the research
([exploration-opencode-v2-native-009](../explorations/exploration-opencode-v2-native-009.md))
found that today ArggonManager integrates with V2 only by accident (skills under
`.agents/skills`, `AGENTS.md`) or by unverified convention (`.mcp.json`), while
V2 offers primitives that map one-to-one onto the workflow: hooks for ambient
context, agents/subagents for orchestration, commands for workflow entry points,
skills for progressive disclosure, sessions/worktrees for per-item isolation,
compaction control, and permissions.

**Invariants (non-negotiable):**

- **I1 — Essence.** `tasks/` stays the single source of truth; the claim →
  worktree → PR → review → merge → done loop keeps its semantics; docs pipeline
  (explorations, ADRs, specs, plans, playbooks, runbooks) unchanged.
- **I2 — One logic path.** Every state transition goes through the kernel
  (`cli/src/rules.ts` and the `run*` commands). The V2 surface surfaces rules;
  it never forks or duplicates them.
- **I3 — Cross-agent.** CLI (human + `--json`) and stdio MCP remain first-class,
  parity-tested and OpenCode-free. No OpenCode dependency in the core; nothing
  in the workflow requires V2.
- **I4 — Generated files.** Bundled artifacts (skills, plugin, agents,
  commands, config seam) are generated by `arggon init` with the existing
  never-overwrite + `x-generated` provenance semantics; sources live in-repo
  with byte-parity tests against the bundled copies.
- **I5 — Optional and graceful.** A missing or failing plugin never blocks the
  CLI, MCP or the work loop; the plugin is a no-op outside ArggonManager trees.
- **I6 — Evidence.** Each wave ships smoke evidence (real `opencode run`
  transcripts for the V2 surface; fixture probes for the CLI), and docs travel
  in the same PR ([docs/engineering.md](../engineering.md) review bar).

**Out of scope (explicit):** npm publishing of a plugin package; `@opencode/sdk`
embedding inside the CLI; a plugin worktree strategy (`arggon start --worktree`
stays authoritative); a TUI plugin (status line/panel) — all deferred with
revisit triggers recorded in [ADR 0010](../adr/0010-opencode2-native-architecture.md).

## Synopsis

Deliverable surface, per wave (plan:
[plan-opencode2-009](../plans/plan-opencode2-009.md)):

```text
opencode.jsonc                  # root config; generated only when the adopter
                                # has none (root or .opencode/), so a later
                                # .opencode/ config overrides ours
.opencode/plugins/arggon/       # vendored plugin (marker + parity test)
.opencode/agents/               # arggon-coordinator | arggon-worker | arggon-reviewer
.opencode/commands/             # /arggon-next, -start, -done, -handoff, -review,
                                #   -status, -spec, -adr, -explore, -playbook
.agents/skills/arggon-cli/      # umbrella skill + references/ (progressive disclosure)
AGENTS.md                       # slim router (generated)
```

- **Plugin behaviors** (ambient only, MCP as the tool surface):
  auto-registers `mcp.servers.arggon` when absent; correlates the session to a
  work item (storage + VCS branch + observed `arggon` calls); injects a bounded
  item block per model call (`session.hook("context")`, `arggon show --json`
  shape); renames the session to the item id on claim; optionally warns when
  `arggon validate` fails after a commit; degrades to a no-op on any failure.
- **CLI/MCP additions (kernel-side, additive):** `_meta.sessionID` defaults for
  `arggon_comment` / `arggon_handoff` attribution; `doctor` OpenCode checks
  (V1-shaped config, artifacts, native registration).
- **Optimization:** detail moves from always-on instructions to advertised
  skills with `references/`; per-item context is bounded and injected only when
  relevant; workers run with isolated context; Code Mode batches multi-tool
  coordinator calls; before/after context accounting uses the existing
  `doctor --budget` surfaces (ADR 0006 spirit).

## Acceptance

- [ ] W0 foundation: ADR 0010 Proposed, this spec and plan merged, tracker
      restructured under epic `opencode2`.
- [ ] W1 declarative seam: `arggon init` generates config (only when absent),
      agents, commands and the slim `AGENTS.md`; never overwrites; provenance +
      parity + JSON-validity tests; `doctor` reports the OpenCode state.
- [ ] W2 plugin core: vendored plugin auto-registers MCP, survives failure
      isolation, and is proven with `opencode run` smoke evidence.
- [ ] W3 session context: item correlation + bounded injection + session rename
      are observable in a real session; `_meta.sessionID` attribution shipped.
- [ ] W4 orchestration: coordinator/worker/reviewer agents + wave flow produce
      the same gates as docs/agents.md (review evidence, smoke gate) in a
      scripted end-to-end run.
- [ ] W5 methodology: `/arggon-spec|adr|explore|playbook` drive the existing CLI
      pipeline; skill split into `references/` with parity tests.
- [ ] W6 context accounting: measured before/after numbers for the V2 prompt
      surface, with regressions called out and fixed.
- [ ] W7 dogfood + release: this repo self-hosts the surface; playbook
      `docs/playbooks/opencode.md` current; README, docs/agents.md and
      docs/json-output.md updated; `arggon validate`, `spec validate` and the
      full test suite green.
- [ ] Essence guardrails verified: CLI and MCP behave identically with the
      plugin absent; no rule logic exists outside the kernel; every generated
      artifact has provenance and a parity test.
