# Spec: Generated OpenCode seam (config, agents, commands) (opencode-seam-010)

## Purpose

W1 of [plan-opencode2-009](../plans/plan-opencode2-009.md). `arggon init` must
leave an initialized repo in a state where an OpenCode V2 session works
**without configuration**: the MCP server is registered, dedicated agents and
workflow commands exist, and no adopter file is ever clobbered. This spec is
the reviewable contract for that generated seam.

Invariants:

- **I1 — Never overwrite.** The seam flows through the existing generation
  machinery: create when missing, regenerate untouched files, skip
  adopter-modified files (with `--backup`, archive then regenerate), skip
  acknowledged baselines. No new bypasses.
- **I2 — Config only when absent.** `opencode.jsonc` is generated **only when
  the adopter has no OpenCode config** (none of `opencode.json(c)` at the root
  nor `.opencode/opencode.json(c)`). When one exists, the destination is
  reported in `skipped[]` with an actionable reason and nothing is written.
- **I3 — Valid syntax.** JSONC files must parse as JSON with comments (no HTML
  marker line — HTML comments are invalid JSON). Markdown artifacts must keep
  YAML frontmatter on the first line.
- **I4 — Visible provenance.** Generated Markdown artifacts carry a visible
  marker: an HTML comment as the first line, or a `#` YAML comment **inside**
  frontmatter when the file starts with `---` (frontmatter-first rule). JSONC
  destinations carry no marker; checksum provenance still applies.
- **I5 — No rule duplication.** Templates contain prompts, descriptions,
  permission rules and pointers to `docs/agents.md` / `docs/engineering.md` /
  the `arggon-cli` skill. They never restate the claim/done/reopen rules as
  alternative semantics, and never call the kernel directly.
- **I6 — Tier-1.** The seam is generated by a plain `arggon init` (not only
  `--full`), because the zero-config promise is the point; it is small and
  bounded.

## Synopsis

```bash
arggon init [dir] [--full] [--backup] [--json]
```

New tier-1 templates → destinations (marker style in parentheses):

```text
templates/docs/opencode.jsonc                    → opencode.jsonc (none; JSONC)
templates/docs/opencode/agents/arggon-coordinator.md → .opencode/agents/arggon-coordinator.md (YAML)
templates/docs/opencode/agents/arggon-worker.md      → .opencode/agents/arggon-worker.md (YAML)
templates/docs/opencode/agents/arggon-reviewer.md    → .opencode/agents/arggon-reviewer.md (YAML)
templates/docs/opencode/commands/arggon-next.md      → .opencode/commands/arggon-next.md (YAML)
templates/docs/opencode/commands/arggon-start.md     → .opencode/commands/arggon-start.md (YAML)
templates/docs/opencode/commands/arggon-done.md      → .opencode/commands/arggon-done.md (YAML)
templates/docs/opencode/commands/arggon-handoff.md   → .opencode/commands/arggon-handoff.md (YAML)
templates/docs/opencode/commands/arggon-review.md    → .opencode/commands/arggon-review.md (YAML)
templates/docs/opencode/commands/arggon-status.md    → .opencode/commands/arggon-status.md (YAML)
```

Path mapping: `templates/docs/opencode/<rest>` → `.opencode/<rest>` (prefix
rule); `opencode.jsonc` maps 1:1 through the explicit destination map.

Generated config content (JSONC, comments allowed): `$schema`, the `arggon` MCP
server under `mcp.servers` (`type: local`, `command: ["arggon","mcp"]`),
`formatter: true`, and a compaction retention (`keep.tokens: 15000`).
`default_agent` is deliberately not set: agents are discovered from
`.opencode/agents/`, and the session default stays `build`. Agents:
`arggon-coordinator` (primary; subagent allow-list worker/reviewer/explore),
`arggon-worker` (subagent; subagent launches denied), `arggon-reviewer`
(subagent; `edit` denied). Commands: prompt templates that drive the MCP tools
(`/arggon-next`, `/arggon-start`, `/arggon-done`, `/arggon-handoff`,
`/arggon-status`) plus `/arggon-review` (`agent: arggon-reviewer`,
`subagent: true`); no shell blocks with argument placeholders.

Result buckets: the ten new destinations appear in `created`/`updated`/
`modified`/`backedUp`/`skipped` exactly like every other generated doc; the
conditional config adds a `present-skip` decision surfaced in `skipped[]`.
`x-generated` records template id, checksum, version and timestamp per
destination, so `doctor` and `init --propose` reason about the seam with the
existing machinery.

## Acceptance

- [ ] A fresh `init` creates the ten destinations; re-runs refresh untouched
      files and skip adopter-modified ones (provenance tests).
- [ ] With a root `opencode.json`, a root `opencode.jsonc`, or
      `.opencode/opencode.json(c)` present, `opencode.jsonc` is **not** written
      and is reported in `skipped[]` with the detected path in the reason.
- [ ] `opencode.jsonc` parses as JSONC and contains no HTML marker; agents and
      commands start with `---` and carry the `# arggon:generated` YAML marker
      as the first frontmatter line.
- [ ] Agents declare the intended modes/permissions (coordinator allow-list,
      worker no-subagents, reviewer edit-deny) and commands declare the
      intended agents/subagent flags.
- [ ] `GENERATED_DOC_COUNT` and the derived counts in `init-docs.test.ts` stay
      green (no hardcoded totals left behind).
- [ ] Docs that describe `init` output are updated in the same PR
      (`docs/agents.md` §Reference integrations, README init notes).
- [ ] `arggon validate` and the full test suite green.
