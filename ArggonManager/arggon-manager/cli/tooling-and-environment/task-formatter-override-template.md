### 2026-10-01 @Arggon — decision + implementation

**Decision: SHIP the override in the generated template** (the recommended option). Rationale: `start --worktree` is the standard arggon layout, so the cwd/`.prettierignore` bypass is guaranteed for every adopter, not incidental; the fix is generic (anchors prettier at the edited file's own git root) and self-degrading (exits 0 when no prettier resolves, e.g. a cold worktree). Document-only would leave every fresh adopter hitting the churn.

Shipped:
- `templates/docs/opencode.jsonc`: `"formatter": true` → the `formatter.prettier.command` override (same command as this repo's #531 fix, strict-JSON-parseable: no trailing commas — `smoke/context-report.ts` and the seam tests `JSON.parse` the generated config). Comment adapted: explains the session-cwd/`.prettierignore` bypass and the git-root anchoring without this repo's incident specifics.
- `cli/src/init-opencode.test.ts`: the W3 config test no longer asserts `formatter === true`; new tests pin the override command shape + anchor semantics (`rev-parse --show-toplevel`, worktree-local prettier, `exit 0` skip) and prove template-vs-generated byte parity + that regeneration keeps the override.
- Adopter migration note in the CHANGELOG `Unreleased` entry: init skips adopter-modified `opencode.jsonc` (existing present-skip tests cover the skip), so existing adopters must hand-apply — the note says where to copy the block from.
- Docs made truthful again: `ArggonManager/docs/agents.md` sample config (methodology carrier — impact class **Advisory**: no rule/gate/command contract/pipeline step changed; the generated-config default content and its doc sample changed) and `ArggonManager/docs/playbooks/opencode.md` (the override is now the template default, not just this repo's local choice).

Impact class: **Advisory** (per the carrier rule, stated here because the PR touches `ArggonManager/docs/agents.md`).
