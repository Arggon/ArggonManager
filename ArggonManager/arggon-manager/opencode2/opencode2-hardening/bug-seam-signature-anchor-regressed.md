# Seam signature anchor regressed: below-JSON comment is claimed again

## Context

`task-opencode2-seam-nits` (PR #346, branch `feat/task-opencode2-seam-nits`) tightened
`isArggonGeneratedConfig` so the `generated by \`arggon init\`` signature is only
trusted on a `//` comment within the file's first two lines. The item is `done`
(coordinator merge verification, 2026-09-18), but the fix is **not in
`opencode2` today** — the current `cli/src/docs.ts` still uses the
first-comment-anywhere lookup (`leadingComment`).

Empirical repro (2026-09-21, primary checkout):

```sh
# init a fixture, then replace opencode.jsonc with:
#   { "formatter": true }
#   // generated by `arggon init`
arggon init <dir> --dry-run --json
# plan[opencode.jsonc].decision == "modified-skip"   (claimed as ours)
# expected after the seam-nits fix: "present-skip"   (adopter config respected)
```

Likely cause: the W0 layout rewrite (`task-native-layout-rename`) reworked
`docs.ts` and restored the older lookup. The failure is in the safe direction
(kept, never clobbered), but it contradicts the docstring ("must not be
claimed") and the merged item's contract.

PR #346 is still an open draft and now conflicts with the v5 layout; it should
be closed as superseded once this port lands.

## Acceptance

- [ ] `isArggonGeneratedConfig` trusts the signature only within the file's
      first two lines (or the docstring is explicitly re-decided and updated —
      prefer restoring the merged anchor).
- [ ] Negative test: signature in a comment after JSON content → `present-skip`
      (adopter config respected), plus the existing NIT-12 string-value case
      stays green.
- [ ] `arggon validate` green; CI green.
- [ ] PR #346 closed as superseded with a comment pointing here; its stale
      worktree/branch cleaned.
