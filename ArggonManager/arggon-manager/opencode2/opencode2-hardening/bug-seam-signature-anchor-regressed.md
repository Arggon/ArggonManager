# Seam signature anchor regressed: below-JSON comment is claimed again

## Context

`task-opencode2-seam-nits` (PR #346, branch `feat/task-opencode2-seam-nits`) tightened
`isArggonGeneratedConfig` so the `generated by \`arggon init\``signature is only
trusted on a`//`comment within the file's first two lines. The item is`done`(coordinator merge verification, 2026-09-18), but the fix is **not in`opencode2`today** — the current`cli/src/docs.ts` still uses the
first-comment-anywhere lookup (`leadingComment`).

Empirical repro (2026-09-21, primary checkout):

```sh
# init a fixture, then replace opencode.jsonc with:
#   { "formatter": true }
#   // generated by `arggon init`
arggon init <dir> --dry-run --json
# plan[opencode.jsonc].decision == "modified-skip"   (claimed as ours)
# expected after the seam-nits fix: "present-skip"   (adopter config respected)
```

Likely cause: the W0 layout rewrite (`task-native-layout-rename`) reworked
`docs.ts` and restored the older lookup. The failure is in the safe direction
(kept, never clobbered), but it contradicts the docstring ("must not be
claimed") and the merged item's contract.

PR #346 is still an open draft and now conflicts with the v5 layout; it should
be closed as superseded once this port lands.

### Evidence — PR #380 (branch `fix/bug-seam-signature-anchor-regressed`)

**What landed.** `isArggonGeneratedConfig` (`cli/src/docs.ts`) restores F1's two-line
window (`content.split(/\r?\n/, 2)`) and pins the generated template's shape: a
line-2 comment only counts when line 1 is the `{` opener (BOM/CRLF-tolerant).
`ArggonManager/docs/json-output.md` `plan` row cross-references the `--propose`
decisions (F2 was missing in opencode2 too).

**Repro — expected vs observed.** Fixture A = this item's literal 2-line repro;
fixture B = PR #346's below-JSON shape (signature comment on line 3):

```
{ "formatter": true }            |  {
// generated by `arggon init`    |    "adopter": true,
                                 |    // "generated by `arggon init`" is what arggon writes
                                 |    "formatter": false
                                 |  }
```

`arggon init <fixture> --dry-run --json` → `plan[opencode.jsonc].decision`:

| fixture    | before (`opencode2`) | exact merged anchor (F1 only) | after (PR #380)    |
| ---------- | -------------------- | ----------------------------- | ------------------ |
| A (2-line) | `modified-skip`      | `modified-skip`               | **`present-skip`** |
| B (line 3) | `modified-skip`      | `present-skip`                | **`present-skip`** |

The merged two-line window alone did NOT fix fixture A — the comment on line 2 is
inside the window — so the opener guard was added. A real `init` leaves A/B bytes
byte-untouched, and the generated config (line-1 `{`, line-2 signature comment)
is still recognized: re-run reports it in `updated[]` on LF and CRLF.

**Tests.** `cli/src/init-opencode.test.ts`: below-JSON comment (line 3) →
`present-skip`; 2-line repro → `present-skip`; generated LF/CRLF shape still
claimed; existing NIT-12 string-value case green. Both new negatives fail against
the pre-fix implementation (scratch copy); the 2-line one also fails against the
exact merged anchor (scratch copy).

**Product decision to confirm.** The item preferred restoring the merged anchor; I

to exact merged semantics if you prefer that.
