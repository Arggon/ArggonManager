# Methodology-first productization: ArggonManager as a standalone methodology with per-agent native adapters

## Context

The way work gets done here — find work, claim it, produce the change, have it
reviewed, merge it — lives scattered across the governing docs and the bundled
helper, but is nowhere declared as the product itself. Anyone arriving should
be able to find, in one hop, what the method is, which version they are
running, and how upgrades reach them; and anyone working through a supported
helper should meet the same rules through that helper's own capabilities, with
the shared kernel named wherever a helper can only assist.

The work groups into three efforts: the role model (who decides what, with the
product owner's calls named and recorded), the external-tooling adopt-or-decline
line (third-party helpers judged against the method's own bars), and the native
adapters plus the methodology carriers as the versioned surface (per-helper
seams chosen at setup, and a matrix stating what each helper can and cannot do
natively). (ADR 0020; ADR 0021; ADR 0022; spec-methodology-adapters-017.)

## Acceptance

Complete when the three epics under it — the role model, the external agent
tooling, and the native agent adapters — are each terminal, and the product
owner has recorded acceptance on this initiative. No separate check applies at
this level; the epics' own completion plus that recorded acceptance is the
whole of it.
