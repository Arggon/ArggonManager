# 0027 Cross-run lessons: promote into the carriers that already own the topic

- Status: Accepted
- Date: 2026-10-13
- Deciders: product owner (Gonzalo), delivery lead (Arggon) — proposed by the maker for `task-spike-cross-run-lesson-store`
- Input: [exploration-cross-run-lesson-store-027](../explorations/exploration-cross-run-lesson-store-027.md) (2026-10-13)
- Methodology impact class: **Behavioral** — it adds a rule agents must re-learn; the implementation PR keeps the skill and its bundled copies in sync and reaches adopters through the ADR 0016 propose channel

## Context

ADR 0022 point 5 took one idea from `autoctx` — **keeping the lessons and discarding the dead ends across runs** — and filed `task-spike-cross-run-lesson-store` to decide whether a durable cross-run lesson store earns its keep on our own substrate, against that record's bar: no second loop, no second executor outside the permission perimeter, no generated moving part in the tree. Adopting `autoctx` was out of scope.

The spike grounded the question in the tracker before designing anything, and the answer changed the problem. Retention is not the deficit: of the tracker's 746 item documents (6,959,940 B), **423 carry a dated comment record** and those records are **3,647,836 B — 52.4 % of the whole tracker**, with the largest single record at 131,535 B. Lessons are written in bulk; they are written **per item**, **unbounded**, and **unindexed**, so the next agent on the same class re-derives them. The repo had already measured the symptom: ADR 0024's context records 10 items as repeat reports of the same class, and `bug-mcp-budget-contradicted-across-docs` (2026-10-03) names its own lesson "same lesson as the baseline-date mismatch" while both items stay open and the class recurs a third time (`task-schema-budgets-near-exhaustion`, 2026-10-12).

What is missing is a **write path**. Everything else already exists and works: `skills/arggon-cli/references/pitfalls.md` states a read contract ("traps that have actually bitten agents in this codebase") and is read on demand; `docs/playbooks/<tech>.md` carries staleness through `arggon playbook status`; `docs/labs/` carries repeatable protocols; the ADR lifecycle carries decisions; a refuted approach filed as an item's `## Context` is durable and greppable. `docs/agents.md` §Documentation maintenance maps **change types** to documents, and no row covers "a trap that bit you" or "an approach this item refuted" — the reader contract has no writer counterpart anywhere.

Three shapes were evaluated against ADR 0022's bar, the third of which is the existing curated-carrier mechanism: a lessons section in the item body (rejected: read only by whoever resumes that item, dies with it, and its checkbox rows are counted by the whole-body acceptance reader the container cascade asks); a per-area note the agent must read before claiming (rejected: no trigger and no enforcement point — the claim path reads the item and nothing else — and one note for everything is either always-loaded or self-rewriting); and the curated carrier (adopted: it is the working mechanism, twice over). The budget made the placement decision: the generated `AGENTS.md` is at 2,031 B of a 2,048 B budget (**17 B free**), the native tool catalog at 12,189 B of 12,288 B (**99 B free**), the MCP `tools/list` at 16,296 B of 16,384 B (**88 B free**), so the trigger cannot go into an always-loaded file and a new command has no budget to exist in.

## Decision

**No lesson store is built.** Lessons are **promoted, bounded and cited, into the carriers that already own the topic**, and the loop gains one trigger sentence — not a new loop, not a new artifact, not a new gate.

1. **The carriers are the storage; each lesson goes to the one that owns its topic.** Loop/tool mechanics → `skills/arggon-cli/references/pitfalls.md`; technology behaviour → `docs/playbooks/<tech>.md`; a refuted approach (a dead end) → the `## Context` of a tracker item; a cross-cutting decision → an ADR. No new directory, no new file type, no new frontmatter key, and no lessons section in the item body.
2. **One line per lesson: one claim, ≤ 160 characters excluding the citation, with a mandatory citation** (`— <item-id>` or `— ADR NNNN`). The rationale stays in the item that produced the lesson. The bound stops the carrier from becoming the unbounded record it is meant to index (the existing pitfalls entry that runs to 4,110 characters is the precedent); the citation is what makes the line supersedable and findable by the PR that changes the mechanism.
3. **The trigger lives in the generated maker prompt, and the rule lives in `docs/agents.md`.** Placement follows ADR 0024 §2 — a capability in the wrong place is absent, and the generated agent files are in `config.generated`, so `doctor` reports the template `outdated` when a repo lags. The generated `AGENTS.md` cannot host it (17 B free).
4. **The promotion moment is the second occurrence.** A maker promotes when the work **repeats** a class another item already met. The standards reviewer checks the promoted line like any other doc that must travel with the change (the existing review bar already makes docs part of "done"); the delivery lead may consolidate a class the tracker shows repeating. No new ceremony, no new role, no new merge step.
5. **Contradiction is resolved by supersede, never by juxtaposition.** A contradicting lesson rewrites the line in place with a dated note naming what changed and which item produced it — the ADR lifecycle's "superseded …, never silently rewritten". Appending a second, contradicting bullet is forbidden: two answers in one carrier with no way to choose is worse than either.
6. **Staleness is per carrier, and the mechanism-less carrier says why.** Technology lessons inherit `arggon playbook status` (`x-playbooks.max-age-days`, default 90). Mechanism lessons carry **no clock**: they expire on an **event** (the mechanism changes), not on a date, so a 90-day rule would fire on true lines and stay silent on the one that just broke. Their invalidation pointer is the citation.
7. **The measurement reuses surfaces that already exist**: `npm run context:report -- --strict` (generated `AGENTS.md`, item block, native catalog) and `arggon doctor --budget` (the ADR 0006 surfaces including the live MCP `tools/list`). One new number, proposed: `references/pitfalls.md` holds **≤ 12,288 B** (9,476 B today), read with `wc -c` when the file is edited. A section that does not fit shortens or supersedes a line; it never raises the ceiling in the same PR.
8. **ADR 0016's propose/absorb channel is inherited where it applies and declined where it does not.** A lesson shipped in `skills/arggon-cli/**` or `templates/**` reaches adopters as a proposal, never by overwrite, and its PR states the impact class. In-tree, git is already propose/absorb; a side-file channel for our own history would be a second, weaker record.
9. **The manual path carries its own falsifier.** If the same class is filed a **third time** after the rule ships, the promoted-carrier path has failed on its own evidence and the question re-opens with that number. Even then, ADR 0022's disqualifier stands: a candidate is re-evaluated only if it captures and replays lessons **inside our loop** — bound by claim discipline, least-privilege permissions and the blocking smoke gate — not as a second loop with its own notion of done and its own history.

## Consequences

- The second agent on a class pays less, and the class stops being refiled — the value hypothesis, deliberately narrower than "agents stop relearning". Nothing here makes an agent read a carrier it has no reason to open, and there is **no index of lessons by class**: an index is the thing that would need a new command, which ADR 0017's ratchet sends to greenfield and the budget findings say is unaffordable today.
- The decision rides on a social trigger, and a social trigger can fail — the failure ADR 0024 measured on `deftai`. Mitigations: placement in the generated file (doctor-visible when stale), the review bar, and the falsifier in point 9. The residual risk is accepted and named, not dismissed.
- `docs/agents.md`, the generated maker prompt and `skills/arggon-cli/**` change in the implementation PR: **Behavioral** impact class, skill and bundled copies byte-equal, adopters reached by `init --propose` as a normal work item. `arggon spec analyze`'s `DECISION-PENDING-EXPLORATION` is satisfied by this record; `STALE-PROPOSED-ADR` (14 days) is the backstop if this ADR merges unaccepted.
- The bounded follow-up is an edit, not a feature: no spec is owed (ADR 0017's hard gate is greenfield-only), and the item that ships it references this record.
- Revisit condition, falsifiable: the same class filed a third time after the rule ships, **and** a candidate that runs inside our loop. Popularity alone never re-opens it.

## Alternatives considered

- **A lessons section in the item body.** Rejected. It costs 0 B per session — the injected item block is frontmatter-only and bounded at 1 KiB — but it is read only by whoever resumes that item, dies with the item, and its checkbox rows are counted by the whole-body acceptance reader the container cascade asks (`cascadeSkipped`), which is the second-grammar class this repo has already fixed twice (`bug-three-acceptance-parsers-diverging`, ADR 0025).
- **A per-area note file the agent must read before claiming.** Rejected. There is no enforcement point ("must read" is advice: the claim path reads the item and nothing else), one file per area produces files no agent opens, and one file for everything is either always-loaded (no budget: 17 B free in the generated `AGENTS.md`) or self-rewriting inside the tree it describes — the `.context.yaml` shape ADR 0022 point 4 and ADR 0006 direction 4 declined.
- **An `arggon lessons` command with an index and a doctor block.** Rejected on two independent grounds: the native tool catalog has 99 B of headroom, and a new command for a new interface is precisely the Phase 0 ratchet's greenfield trigger. If a future measurement shows the manual path failing (point 9), this is the shape to spec — through ADR 0017, not by amendment here.
- **Adopting `autoctx`'s automatic capture and replay.** Rejected, unchanged from ADR 0022: a second loop with its own notion of done and its own history, an executor outside the permission perimeter, and a generated moving part in a tree whose fixed surfaces have no room for it. This record adds the measurements; it does not reopen the decision.
- **A 90-day staleness clock on mechanism lessons, copied from `playbook status`.** Rejected on the mechanism's own terms: the clock answers "has this research aged", and a mechanics lesson does not become false with age — it becomes false when the mechanism changes, which is an event with an author and a PR. Copying the clock would fire on lines that are still true and stay silent on the line that just broke.
