# 0012 Tracker root and product docs layout: `ArggonManager/`

- Status: Accepted
- Date: 2026-09-19
- Deciders: product owner (Gonzalo), coordinator/architect (Arggon)
- Related: [ADR 0011](0011-native-first-architecture.md) (native-first surface; this ADR amends its data-location decision)
- Program: `task-native-layout-decision` · migration `task-native-layout-rename`

## Context

Product-owner directive (2026-09-19), confirmed while accepting ADR 0011:

- The tracker root is renamed `tasks/` → `ArggonManager/`.
- **All product docs** live under `ArggonManager/docs/`: adr, specs, plans,
  explorations, playbooks, convention/engineering docs, and the docs generated
  by `init`.
- Legacy `tasks/` trees must keep working: the kernel auto-detects them and
  migrates (no hard break).

Today the convention fixes the tracker at `tasks/` and spreads product docs at
the repo root (`docs/`). The rename gives ArggonManager one owned root per
repository and makes the "what is ArggonManager" boundary explicit.

## Decision

1. **Tracker root**: items live under
   `ArggonManager/<initiative>/<epic>/<story>/`; `ArggonManager/.convention.yml`
   replaces `tasks/.convention.yml`.
2. **Product docs**: every ArggonManager doc moves under `ArggonManager/docs/`
   (adr, specs, plans, explorations, playbooks, convention, engineering,
   agents, json-output, plus the docs generated by `init` such as
   `tracking.md`).
3. **Compatibility**: the kernel detects a legacy `tasks/` tree and either
   operates on it (read paths) or migrates it to `ArggonManager/` through the
   convention migration command; `validate` reports the legacy location. No
   hard break for existing adopters.
4. **Convention version**: the layout change bumps the convention version. The
   current `.convention.yml` stays at its numeric version, and `v4` is already
   taken by the priority schema, so W0 must disambiguate the numbering and
   record the bump; the migration is the supported path.
5. **Dogfood**: this repository migrates its own tree and docs as the first
   adopter (tracked by `task-native-layout-rename`).

## Consequences

- **Positive**: one owned root; unambiguous boundary; docs travel with the
  tracker; simpler adoption and cleanup; links can be repo-relative to a single
  root.
- **Negative / accepted**: a convention-breaking rename with a broad mechanical
  diff (kernel paths, CLI/MCP messages, generated seam, templates, skills,
  commands, docs links, CI); migration tooling and tests are required; external
  references to `tasks/` break until migrated.
- **Neutral**: item ids, frontmatter and the methodology are unchanged.

## Alternatives considered

- **Keep `tasks/`** — rejected: the product owner wants a single
  `ArggonManager/` root with docs inside it.
- **Hard break (no legacy detection)** — rejected: breaks every existing
  adopter; migration is cheap to support.
- **Only the tracker renamed, docs elsewhere** — rejected: the owner wants all
  product docs inside the root.
